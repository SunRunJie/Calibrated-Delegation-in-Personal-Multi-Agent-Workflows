# 日志编码手册（研究2 · 内容分析）

> 分析对象：成员导出的时间轴日志（timeline.md）、记忆文件与代表性对话记录。
> 分析单元：一次"委托事件"——用户将某一环节的任务交付给Agent，直至产生结果或用户收回。
> 信度要求：2名编码者独立编码20%样本，Cohen's κ≥0.70（程序：`07-数据分析程序/02-日志编码信度.py`）。

## 一、任务流环节（stage，单值）

| 编码 | 含义 | 判断要点 |
|---|---|---|
| 需求界定 | 明确目标、澄清需求、定义问题 | 对话以"我要做什么""帮我理一下目标"开始 |
| 信息检索 | 搜索、查资料、找信息 | 结果指向外部信息源 |
| 信息整理 | 归纳、结构化、做笔记、摘要 | 对已有材料进行重组 |
| 分析推理 | 数据分析、逻辑推演、利弊分析 | 产出含判断过程 |
| 内容生成 | 写作、文案、方案草稿、代码生成 | 产出为文本/代码等制品 |
| 执行操作 | 发邮件、改文件、跑程序等实际动作 | 涉及对环境的修改 |
| 判断决策 | 做选择、下结论、给立场 | 产出为最终结论 |

规则：一次事件归属一个主要环节；涉及多个环节时，以用户最初委托的环节为准。

## 二、结果（outcome，单值）

| 编码 | 含义 |
|---|---|
| 成功 | 产出满足指令，用户未要求返工即采用 |
| 部分成功 | 部分满足，经修改后采用 |
| 撤回 | 用户中途取回任务自行完成 |
| 失败 | 产出不可用，被放弃或需重做 |

## 三、失败原因（fail_reason，仅失败/部分成功时填写）

| 编码 | 含义 |
|---|---|
| 能力不足 | 它做不了或做不好 |
| 输出不可靠 | 质量不稳定、遗漏、跑题 |
| 不省时间 | 解释与检查成本高于自行完成 |
| 隐私顾虑 | 涉及敏感信息而中止 |
| 情感需求 | 用户希望自己完成 |
| 其他 | 其他（在备注注明） |

## 四、迭代次数（iterations，整数）

用户与Agent在该事件内的往返轮数（用户发指令/纠正一次计1轮）。

## 五、错误暴露方式（error_exposure，单值）

| 编码 | 含义 |
|---|---|
| 当场发现并纠正 | 错误在会话内被核查或用户当场发现并纠正 |
| 事后发现 | 错误在会话结束后才被发现 |
| 未发现 | 无错误记录，或错误未被察觉 |

规则：结果=成功且无纠错记录时填"未发现"；结果=失败/部分成功时，结合用户话语判断"当场/事后"。

## 六、编码流程

1. 主编码者（编码者A）通读日志，按时间顺序切分委托事件，填写主编码列（stage/outcome/fail_reason/iterations/error_exposure）。
2. 从全部事件中随机抽取20%作为样本行，复制给编码者B独立填写 `coderB_*` 列（不看A的结果）。
3. 运行 `02-日志编码信度.py` 计算各维度Cohen's κ。
4. κ≥0.70：分歧协商统一，A完成全量编码；κ<0.70：回到手册澄清定义，重新编码样本直至达标。
5. 编码完成后运行 `03-委托边界与假设检验.py` 生成委托边界与假设检验数据。
